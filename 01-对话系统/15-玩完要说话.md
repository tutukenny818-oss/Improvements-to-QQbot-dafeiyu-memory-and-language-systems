# 第 213~214 轮 · 玩完就不说话 / 工具里的限制文案

> 用户 2026-10-22：
> ① 「它在玩完游戏后就不说话了，要是有活人感的话一般会吐槽吐槽的吧」
> ② 「工具里都在教它『别刷、别重复、别废话』是为什么啊，我其实并不希望这样的，
>    就像我让它刷视频和玩游戏都是想玩就玩，没有说有啥限制来着」

---

## 〇、两件事的结论

**① 玩完不说话：不是不会吐槽，是没人告诉它该说。**

它**开局时**是会说的（真实发言）：

```
@果壳  /牛牛 60  都输成这样还下60……就125了，留点壳币明儿个还吃饭呢
@果壳  /五连抽  我说的吧，全重复，血亏
```

但**结果回来之后**，工具回执只说「等果壳回」，没有一个字提示「回完接一句」。
而它上下文里全是「别刷」「别废话」「别重复」——于是它自己在 11:49 那轮写道：

> 「连刷不好，先放一放」「这一轮**不发言**，不调用任何工具」

**它是在自我克制，不是不会。**

**② 那些限制文案的来历：是历史需求的错误实现。**

翻遍 `plugin.py` 的注释，每一条限制都有出处，但**没有一条是用户要「少玩」**：

| 文案 | 出处 | 用户真正说的 |
| --- | --- | --- |
| `daily_limit = 4` / `min_gap_minutes = 90` | 第 164 轮 | 「怎么都跟固定任务一样」——嫌**像闹钟**，不是嫌多 |
| 「别老是同一个」 | 第 164 轮 | 「只会去玩牛牛」——嫌**单调**，不是嫌次数 |
| 「一天一两次就够，刷多了像自检」 | 第 165 轮 | 要求「告诉它有哪些功能」——被加成了限量 |
| 「别在群里正热闹时开」 | 早期 | 技术顾虑（一局耗时长）——被写成了禁令 |
| 「别在群聊里回『算出来了』之类的废话」 | 早期 | 怕它耽误交答案——被写成了禁止说话 |

**「别像固定任务」被实现成了「少玩、别玩」，这是理解偏差。**

## 一、第 213 轮：让它在玩完之后说话

### 1.1 改哪里

`play_guoke_command` 的工具回执（`plugin.py:1322`）新增：

```
💬 等果壳把结果发出来之后，说两句 —— 这是这局的一部分，不是加戏。
   · 赢了就嘚瑟、输了就嘴硬、结果离谱就吐槽，想说什么说什么
   · 想多说两句也行，跟群友聊球一样自然就好
   · 用 reply 直接说，不要再塞进 @果壳 的指令里（那样它读不到）
```

`answer_guoke_game` 的回执同样补一句。

**为什么不让插件自己发吐槽**：插件发的是固定模板，那才是真的没人味。
吐槽必须由模型现编，这里只提醒「该说话了」，说什么由它决定。

### 1.2 第二道闸：果壳的战况被门控拦掉

修完回执还不够。实测门控对果壳的结果消息：

```
'🪙 壳币不够：五连包 220，你现在有 80。'        → allow=False S1 别人闲聊
'🏆 果壳图鉴排行榜（27 人参与 · 按积分）'      → allow=False S1
'你赢了！+25 壳币'                          → allow=False S1
```

**这些恰恰是大肥鱼自己参与那局的回执，判「别人闲聊」直接拦掉。**

`activation_gate.py` 新增 `_BOT_GAME_RESULT_PATTERN`：
要求「玩法专属词」和「结算/提示形态」同时出现，收得比较紧：

```python
_GAME_WORDS = r"壳币|果壳|图鉴|抓壳|五连抽|牛牛|井字棋|扫雷|猜词|24点|硬币|天才|圈果壳"
_GAME_RESULT_FORMS = r"不够|余额|排行|进度|结算|赢了|输了|+N 壳币|第N问|点下面的按钮|..."
```

验证 12/12：

```
[PASS] 🪙 壳币不够：…          → allow=True  I2
[PASS] 你赢了！+25 壳币         → allow=True  I2
[PASS] 今天吃了碗面，有点咸      → allow=False S1   ← 普通闲聊仍拦
[PASS] 大肥鱼今天怎么没说话      → allow=False S2   ← 第三人称仍拦
```

## 二、第 214 轮：拆掉那些限制

### 2.1 清除劝阻型文案（6 类全部归零）

| 类型 | 改前 | 改后 |
| --- | --- | --- |
| 别刷/别重复 | 5 处 | 改为「同一句别一字不差连发两遍」（防重复提交，技术必需） |
| 别废话 | 4 处 | 0 |
| 像自检/打卡/固定任务 | 12 处 | 0 |
| 别老是同一个 | 2 处 | 「想玩哪个就玩哪个，没有该换着玩的规矩」 |
| 别在热闹时开 | 2 处 | 「想玩就玩，群里热闹可以边下边聊」 |
| 别连发 | 2 处 | 0 |

具体例子：

```
改前：⚠️ **别老是同一个** —— 天天同一局像打卡，换着玩才像人。
改后：⚠️ **想玩哪个就玩哪个** —— 没有「该换着玩」的规矩，喜欢就一直玩同一个，
      开心比花样多重要。

改前：这些查询类一天发一两次就够，发多了像机器人自检。
改后：这些查询类随便用，想知道就查，一天查几次都行 ——
      只要别把同一句一字不差地连着发两遍。

改前：⚠️ 一局要下挺久，**别在群里正热闹的时候开**。
改后：⚠️ 一局要下挺久（几十步），想下就下 —— 群里正热闹的话，你可以边下边跟人聊。

改前：今天玩不了（…）。**别再试别的玩法**，就当这次没想起来。
改后：这次玩不了（…）。想玩点别的随时可以。
```

**保留的 2 条**（有正当技术理由，不是限制）：

- 「带参数的指令不要自己拆开发」—— 拆开果壳不认（第 132 轮的坑）
- 「同一个答案别发两遍」—— 果壳同一副题只算一次

### 2.2 放开 proactive 频率

```diff
 [proactive]
-interval_minutes = 120    # 平均 2 小时想起来一次
-daily_limit = 4           # 一天最多 4 次
-min_gap_minutes = 90      # 两次至少隔 90 分钟
+interval_minutes = 45     # 45 分钟一次（实际 27~99 分钟，有抖动）
+daily_limit = 0           # 0 = 不限
+min_gap_minutes = 20      # 只防同一分钟连开两局
```

`[play]` 三项本来就是 0（不限），没动。

### 2.3 时机因子：冷群不再被推迟

`src/maisaka/utils/timing_factor.py`：

```diff
-FACTOR_STALE = 1.8   # 冷 → 等待拉长（别硬找话）
+FACTOR_STALE = 1.0   # 冷 → 不额外拉长（想玩就玩，冷群本来就是主场景）
```

**为什么这条也该改**：`FACTOR_STALE = 1.8` 是第 206 轮按「别硬找话」加的，
但这个插件的触发条件本来就是「**群里没人说话，你自己想起来去玩**」。
冷群才是它的主场景 —— 冷的时候反而少玩，逻辑自相矛盾。

改后实测（base = 45 分钟）：

```
距上条    1 分钟 → 等  20.2 分钟  factor=0.5  （热，提前参与）
距上条   30 分钟 → 等  41.1 分钟  factor=1.0
距上条  180 分钟 → 等  41.0 分钟  factor=1.0  （原来是 112 分钟）
距上条  600 分钟 → 等  40.4 分钟  factor=1.0  （原来是 112 分钟）
```

**「热 → 提前」保留**：那时候群里有人看着，参与感更强，方向是对的。

## 五、还差的验证

| # | 验证什么 | 怎么看 |

| 1 | 玩完真的会吐槽 | 日志里 `play_guoke_command` 之后同轮出现 `reply` |

**第 4 条要盯**：放开频率的代价是凌晨也可能在玩。真吵了就调 `interval_minutes`，
