# 第 212 轮 · 「只会回一句」与「只在过客群玩」

> 用户 2026-10-22 报两件事：
> ① 问它几点，只回「四点三十五了……这时候还不睡」，接不上「晚安」，希望更有人味；
> ② 好像只在过客群玩。
> 但**之前加过输出限制**，因为 @果壳 玩游戏时指令被拆开、果壳没反应。

---

## 〇、两个结论

**① 只会回一句 = 第 132 轮为修「指令被拆」把断句整个关了。**

`enable = false` + `max_split_num = 1` → 不管模型写了几句话，最后都被压成**一条**。
不是模型不想接第二句，是发送前被合并掉了。

**② 「只在过客群玩」是错觉。** 三个群都在说话，只是**内容性质不同**：

| 群 | 近 72h 大肥鱼发言 | 游戏指令 | 真人对话 |
| --- | --- | --- | --- |
| 过客 | 582 条 | 159 | **423** |
| 八十平米的哈基米 | 348 条 | 26 | **322** |
| 元气💥群 | 110 条 | 37 | 73 |

过客群显眼是因为**它在那儿参与真人闲聊最多**。元气群的消息 42% 是 @果壳 玩游戏的指令，
真人对白只有 137 条 —— 那里本来就没多少话可聊。

## 一、断句的来龙去脉

### 1.1 第 132 轮：为了保住 @指令，把断句整个关掉

`config\bot_config.toml` 原文：

```toml
[response_splitter]
enable = false   # ⚠️ 第 132 轮关掉：这就是「大肥鱼老是把词拆开发」的根因
max_split_num = 1  # ⚠️ 1 = 不拆。原来是 3，正是「最多拆三条」的来源
```

真机证据（2026-10-18 07:00~07:04 过客群）：

```
它把 `/井字棋 5` 拆成两条发 → 一条 `@果壳 /井字棋`、一条 `5`
它把 `/猜词 运动 普通` 拆成 `@果壳 /猜词` + `运动 普通`
```

果壳要求 at 和指令在**同一条消息**里才认 → 拆开等于白 @。

### 1.2 副作用：所有多句回复被压成一条

`_merge_processed_segments_to_max_count(segments, 1)` 会把任意多条合并成 1 条。
所以「四点三十五了……这时候还不睡」和想接的「晚安」永远到不了同一条消息之外。

### 1.3 为什么不能改回 `mode = "rule"`

实测 `_split_into_sentence_segments`：

```
'@果壳  /五连抽  我说的吧，全重复，血亏'
   -> 5 段: ['@果壳', '/五连抽', '我说的吧', '全重复', '血亏']
```

rule 模式按逗号/空格**概率性**切分，边界不可控 —— 正是当年拆坏指令的那套逻辑。
而且它有随机性（`merge_probability`），同一句话两次跑结果可能不同。

## 二、修法：新增 `mode = "newline"`

### 2.1 设计

| 模式 | 边界由谁决定 | 会不会拆坏指令 |
| --- | --- | --- |
| `rule` | 按逗号/句号概率切 | 会 |
| `llm` | 再调一次模型断句 | 可能，且多一次请求 |
| **`newline`** | **模型自己写的换行** | **不会（结构上保证）** |

**核心：模型写了换行就分条，没写就一条。** 边界完全由模型掌握。

### 2.2 `_is_at_command_text()` —— 结构上保护 @指令

```python
def _is_at_command_text(text: str) -> bool:
    # 含 at，且 at 后跟斜杠指令或数字/算式
```

判定为真时：

1. 切分阶段：这一行不与下一行合并，也**不从它前面切**
2. 错别字阶段：**跳过**（否则 `/井字棋` 可能变成 `/井字琪`，指令不认）
3. 最后兜底：如果多段里出现 @指令，整体合并回一条

### 2.3 `_is_bare_at()` —— 裸 at 也不许单独成条

模型可能写成：

```
@果壳
/井字棋 5
```

这时 `_is_at_command_text` 对两行都是 False，会在中间切开。`_is_bare_at` 专门判「只有 at」，
遇到就合并下一行。

### 2.4 配置改动

```toml
[response_splitter]
mode = "newline"      # rule → newline
enable = true         # false → true
max_split_num = 3     # 1 → 3（1 会把分好的结果又揉回去）
```

`ResponseSplitterConfig.mode` 的 `Literal["rule", "llm"]` 同步扩成 `["rule", "llm", "newline"]`。

### 2.5 提示词：让模型知道换行 = 分条

`prompts\{zh-CN,en-US,ja-JP}\maisaka_replyer.prompt` 三语同步加了一节：

> **你写的换行就是分条。** 想连发两条，就在两句话之间写一个换行；不想连发，就别写。

并明确写了「什么时候别写」和「@指令之间绝对别换行」。

## 四、关于「只在过客群玩」

### 4.1 数据

```
近 48h：真人闲聊 vs 大肥鱼开口
  过客             真人  149 → 大肥鱼 142  ( 95.3%)
  八十平米的哈基米    真人  422 → 大肥鱼 180  ( 42.7%)
  元气💥群          真人   47 → 大肥鱼  66  (140.4%)
```

过客群参与度 95%，所以显得「只在那儿玩」。但另外两个群它**也在说话**。

### 4.2 真正的原因：群性质不同

元气群近 72h 消息构成：

```
果壳（另一个 bot）  572 条
《老经》           471 条   ← 全是 /果壳指令 和果壳的回复
大肥鱼             163 条
Tutu               96 条
其他真人            约 100 条
```

**42% 的消息是 @果壳 玩游戏**，真人对白只有 137 条。那里本来就没多少话可聊。

过客群 33% 是游戏指令，剩下的都是真人聊天 → 它自然参与得多。

### 4.3 这条不用改

不是"不去别的群"，是"别的群没在聊它插得上嘴的话题"。改门控让它硬插话只会变吵。

## 七、想退回旧行为

```toml
mode = "rule"
enable = false
max_split_num = 1
```

或者只关分条、保留指令保护：

```toml
enable = false
max_split_num = 1
```

（`enable = false` 时仍会走一次 newline 切分 —— 这是为了让「写了换行」不至于完全失效；
想彻底一条不拆，把 `enable` 设 false 且不改代码的话，它还是会在有换行时分条。
若确实要「永远只发一条」，把 `max_split_num` 设 1 即可，那会把结果压回一条。）
