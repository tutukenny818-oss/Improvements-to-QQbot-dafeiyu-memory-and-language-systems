## 一、三个独立的问题叠在一起

### 1.1 「好吧看来你找不到」被判 S1 闲聊

这句话没有名字、没有问号、没有指令词 —— **单看它确实像闲聊**。

但它在**一段正在进行的一对一对话里**：Tutu 刚问它问题，它刚回答了，这句是在评价它的回答。

门控只看文本，看不到「这段对话正在跟它进行」。

### 1.2 贴表情被当成「已经回应过」

`human_touch` 的 react 回执原来只有一句：

```
贴上了。
```

模型理解成「回应完成了」。**但群里看到的只是一个斜眼笑小图标，一句话都没有。**

用户观感就是「怎么没反应」。

### 1.3 连拦两次 → 它主动放弃了 reply

第 209 轮定的规则「同一个 msg_id 别反复重试」起了作用 —— 它试两次就换路子了。
**规则是对的，是门控在误杀。**

---

## 二、三处修法

### 2.1 新增「对话连续性」判据（主修）

```python
# 只要 bot 刚在这段对话里发过言，对方说什么都算在跟它说话
if _bot_spoke_recently(recent_texts, recent_authors, bot_aliases=alias_list):
    return ActivationDecision(True, "I2", "它刚在这段对话里发过言，对方在接它的话", 0.7)
```

**为什么比第 218 轮的「接续短句」更宽**：接续短句还要求文本像「继续/好/行」，
而这里对方可以说任何话（「好吧看来你找不到」「怎么判断的这是」）——
**只要对话是连续的**就成立。

**为什么不会变话痨**：只覆盖「bot 刚说完、对方马上接」这一种情形。
一群人自己聊天时 bot 没插过话，`recent_authors` 就是 False，不命中。

### 2.2 回看深度从 1 条扩到 3 条

原来只看 `latest_index` 前**一条**。但现实中常夹着打断：

```
大肥鱼: 开了
果壳:   这局已经猜中了…（结算）
过客:   再来一局          ← 中间隔了果壳，链断了
```

现在往前看 `_CONVERSATION_LOOKBACK = 3` 条，容得下短打断。

### 2.3 贴表情必须说清「这不等于说话」

`human_touch` 的工具描述 + react 回执都改了：

```
⚠️ **这些动作都不出声**。对方只看到一个小图标/一条系统提示，看不到任何内容。
**该说的话还是得用 `reply` 说** —— 别用「我贴了个表情」当作已经把话说完了。
```

回执里也补了同样的提醒。

### 3.1 事故原句重放

```

### 3.2 不能放开的情况

```

  '好吧看来你找不到'  → S1  拦

  '这个真不错'        → S1  拦（最近一条不是 bot）

## 六、这轮最该记住的

**模型的行为链是「尝试 → 被拦 → 换方案 → 以为完成」。**

它每一步都做对了：

- 搜了（web_search）
- 想回（reply × 2）
- 被拦后没有死磕（换成不涉及门控的动作）
- 贴表情时自己也知道「光贴表情不等于把话说清」

**问题全在门控误杀 + 回执措辞。**

所以排查「怎么没反应」时，不能只看最后一轮。要看**它试过什么、被什么拦住了**。

日志里的 `激活门控拦截 reply：S1` 就是那两枪。
