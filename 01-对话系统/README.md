# 01 · 对话系统：它什么时候说话

> 这一层是整个项目最花时间的部分。
> **核心原则：沉默是安全的默认值。**

---

## 为什么「该不该说」比「说什么」难

依据 [Speak or Stay Silent (arXiv:2603.11409)](https://arxiv.org/html/2603.11409v1)：

> "context-aware turn-taking is **not an emergent capability**; it must be explicitly trained."

8 个 LLM 零样本全失败，最好的 64.45%。

**我们自己的实测**（1200 条消息样本）：

| 类别 | 期望 | 说话率 | 判定 |
| --- | --- | --- | --- |
| I1 被 @ 点名 | 该说 | 81.8% | ✓ |
| I2 该回应 | 该说 | 21.1% | ⚠ 偏低 |
| **S1 别人闲聊** | **该静** | **70.7% 插话** | ★ 严重 |
| **S2 被提及没被对话** | **该静** | **61.9% 插话** | ★ 严重 |

**两个根因**：
1. `talk_value = 1.0` → 触发阈值 = 1 → 每条消息都进 Planner
2. Planner prompt 写着「**其他情况都需要调用工具**」→ 强制行动

---

## 四分类（最终形态）

| 类别 | 判据 | 动作 |
| --- | --- | --- |
| **I1** 直接叫你 | `@它` / 叫名字+指令 / **名字+动词+量词**（「大肥鱼猜一个」） | **必须回** |
| **I2** 话题需要你 | 提到它+问号 / 玩法结算 / **第二人称+疑问** | 回 |
| **S1** 别人闲聊 | 没提它、没问号 | 拦（15% 概率放行） |
| **S2** 提到你没跟你说 | 「大肥鱼今天怎么没说话」这类第三人称 | 拦（15% 概率放行） |

**保留 15% 放行**是有意的 —— 100% 拦截太生硬，真人也会偶尔插一句。

---

## 光有分类不够，还要看上下文

单看一条消息的文本，会漏掉大量真实场景。后来补的这些判据**全部是故障逼出来的**：

| 场景 | 单看文本会怎么判 | 补充判据 |
| --- | --- | --- |
| 「大肥鱼！」+「不出来伤心了」两条连发 | 只看最后一条 → S1 拦 | **窗口回看**：窗口内任意一条是 I1 就放行 |
| Planner 要回「又不回答了」，缓存最新是表情包 | 表情包没名字 → S1 拦 | **按 msg_id 定位被回复的那条** |
| 「再来一局」（它刚玩完一局） | 没名字没问号 → S1 拦 | **接续短句**：bot 刚说完 + 短句像继续 |
| 「好吧看来你找不到」（它刚回答完问题） | 没名字没问号 → S1 拦 | **对话连续性**：bot 刚在这段对话里发过言 |
| 有人引用它说的话回复 | 文本里没名字 → S1 拦 | **引用归属**：读 ReplyComponent 看被引用者 |

## 延迟从哪来

即使判定放行，还有一层「什么时候真的开始想」：

```
消息进来
  ↓
① 连发合并窗口        2.0 秒（把你连打的几句合成一批）
  ↓
② 触发阈值            ceil(1/talk_value) = 2 条
  ↓ 只有 1 条时
③ 空窗补偿            等「平均消息间隔」（限 15~120 秒）
  ↓
④ Planner 思考        实测 3~9 秒
  ↓
⑤ replyer 生成        实测 2.5~4 秒
```

**被 @ 或被叫名字走强制触发，跳过 ②③ —— 所以是 6~13 秒。**
**普通消息要等 15~120 秒 + 6~13 秒。**

> 曾经这里出过大事：平均间隔没有上限，冷群一次算出 **等 67 分钟**。
> 见 [05-延迟67分钟](05-延迟67分钟.md)。
