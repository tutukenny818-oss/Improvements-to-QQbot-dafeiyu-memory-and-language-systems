## 二、为什么没人发现（这轮最值得记的一条）

`src\maisaka\planner_reply_guard.py` 早就实现了 `has_unsent_reply_intent()`，
能把这种正文识别成「想回复但没调工具」。

实测：

```python
has_unsent_reply_intent(那条正文)  # → True
```

但它的开关 `experimental.planner_unsent_reply_retry` **一直是 `false`**
（`official_configs.py:968` 的默认值就是 False）。

于是统计出来：

| 项 | 数量 |
| --- | --- |
| 当天 `Planner 已结束本轮思考` | **16 次** |
| 其中 `表达了回复意图但未调用工具，已提醒并重试` | **0 次** |

**机制写好了、测试过了、开关没开 = 等于没有。**

## 三、修复

### 3.1 改了什么

`config\bot_config.toml:70`

```diff
- planner_unsent_reply_retry = false
+ planner_unsent_reply_retry = true
```

备份：`config\bot_config.toml.bak_p207_unsent_retry_20261022_015306`（哈希一致校验过）

### 3.2 生效方式：热重载，不用重启

改完 20 秒内日志自己出现：

```
01:53:26  配置热重载命中的配置节: ['experimental']
01:53:29  配置热重载完成
```

`global_config` 是 `_ConfigProxy`（`config.py:926`），每次读都走 getter，所以新值立刻生效。

### 3.3 打开后的行为

```python
if (planner_unsent_reply_retry and planner_no_tool_count == 0
        and has_unsent_reply_intent(planner_content)):
    # 追加 ReferenceMessage(PLANNER_UNSENT_REPLY_HINT)，重跑一轮
```

提醒原文（`reasoning_engine.py:110`）：

> 你上一轮的输出没有调用任何工具，聊天里没有出现任何新消息：你的文字输出只有你自己能看到。
> 如果你打算发言，必须调用 reply 工具；如果你决定不发言，直接结束即可，不需要解释。

**每个回合最多重试一次**，重试后仍不调工具就正常收尾 —— 不会死循环。

## 五、顺手排除的两个「看起来像但不是」的原因

### 5.1 不是门控拦的

如果 Planner 真的调了 reply，门控会怎么判？实测：

```python
evaluate(latest_text="今天先不忙你的事了大肥鱼", is_at=False, is_mentioned=True)
# → allow=True, kind=I2（平台判定提及 bot）
```

生产路径上 `runtime.py:1378` 已经把 `message.is_mentioned = True`（名字/别名命中），
所以门控会**放行**。这条消息本来不会被拦。

### 5.2 不是「还没到阈值」

```
:436  待处理=1 阈值=2 频率=0.500 判定=延迟检查
:442  待处理=2 阈值=2 达到阈值=2 判定=进入Planner
```

两条消息攒够阈值，**确实进了 Planner**。

## 七、六条排查路径（下次「没回应」按这个顺序）

```powershell
$f = (Get-ChildItem D:\MaiBot\logs -Filter 'app_*.jsonl' | Sort LastWriteTime -Desc | Select -First 1).FullName

# 1. 消息进来了吗
Select-String -Path $f -Pattern '<关键词>' | Select -Last 5

# 2. 进 Planner 了吗
Select-String -Path $f -Pattern '进入Planner|判定=延迟检查' | Select -Last 5

# 3. Planner 输出里有工具吗（最容易被忽略的一步）
#    看 logs\maisaka_prompt\planner\<chat>\<ts>.json 的 output_items
#    只有 AssistantMessageItem = 想完就结束，不会有任何消息发出

# 4. reply 工具跑了吗
Select-String -Path D:\MaiBot\logs\app_*.jsonl -Pattern 'maisaka_builtin_reply'

# 5. 门控拦了吗
Select-String -Path D:\MaiBot\logs\app_*.jsonl -Pattern '激活门控'

# 6. 适配器策略拦了吗（入站就被丢）
Select-String -Path $f -Pattern '入站被策略拦截|Host 丢弃了'
```

**第 3 步是这轮新增的** —— 前三步都正常、第 6 步也没拦，问题就只可能在
「Planner 想说但没调工具」或「reply 执行失败」两者之间。
