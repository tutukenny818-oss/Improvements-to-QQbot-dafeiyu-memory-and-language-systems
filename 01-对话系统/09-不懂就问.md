## 〇、先说结论

现有黑话学习**全是被动的**，缺一条主动链路：

| 通路 | 触发条件 | 缺口 |
| --- | --- | --- |
| `jargon_miner` 词频挖掘 | 同一个词在群里出现 **≥4 次** | 冷门词永远轮不到 |
| `apply_explicit_definitions` | 群友**主动**说「X 就是 Y」 | 得等别人主动解释 |

**没有「我不懂 → 我问 → 别人答 → 记下来」这条路。**

新增 `ask_term` 工具补上这一环。

---

## 一、这个工具做什么

```
模型看到「灯丝把」，不确定什么意思
  → 调 ask_term(term="灯丝把", msg_id=那条消息)
  → 在群里说「@某人 灯丝把是啥意思」
  → 群友回「谐音，等死吧」
  → extract_explicit_definitions() 认出这个句式 → 直接写进 jargons 表
```

**答复会自动入库** —— 因为第 142 轮已经实现了 `apply_explicit_definitions`：
只要词在库里、群友给出明确释义，当场 `is_complete=True`，不再重复推断。

## 二、四条边界（防止用歪）

### 2.1 不许装不懂

```python
if _is_known(term):
    return failure("「X」你其实知道是什么意思，别装不懂 —— 直接接话就行。")
```

实测：

```
牛牛      known=True   （在库+有释义）→ 拒绝问
壳币      known=True                 → 拒绝问
啥鱼      known=True                 → 拒绝问
灯丝把    known=False  （不在库）     → 可以问
半讽半认  known=False  （在库但无释义）→ 可以问
```

> 「半讽半认」这条特别值得注意：它在库里但 `meaning` 是空的。
> 这种情况**该问** —— 有词无义等于不知道。

### 2.2 同一个词 24 小时内只问一次

一天问两遍同一个词，在群里看着就是「它没记住」，比不问更减分。

### 2.3 只问词，不问事

长度上限 **12 字**。超过的当作「半句话」拒绝：

```
「灯丝把」            → 可以问
「日常用品」          → 可以问
「这个东西到底该怎么办」 → 太长了，那是正常聊天的事，不是查词
```

### 2.4 答完要接一句

工具回执里写死了：

```
· 有人解释之后，**接一句**（别问完就没下文）
· 答复会自动记进黑话库，下次不用再问
· 这轮别再就同一个词追问第二次
```

**问完不说话，比不问更怪** —— 像查完字典就把人晾那儿。

## 三、为什么不复用 reply

`reply` 也能问，但它：

1. 会走 replyer（再调一次模型润色）—— 问一个词不需要那么重的管线
2. **不会在库里留标记** —— 事后无法区分「真没懂才问」还是「在闲聊」
3. replyer 可能把要 @ 的人改掉

所以 `ask_term` 自己发，并且负责两件事：
**查库判断该不该问** + **登记冷却**。

## 五、和「参与闲聊」的关系

用户这条提议的上下文是「咱们要不让大肥鱼参与闲聊也可以吧，就是别把别人回复别人当成回复自己」。

两件事其实是配套的：

| 需求 | 做法 |
| --- | --- |
| **别把别人回复别人当成回复自己** | 第 196 轮的「引用归属」+ 本轮在 `reply.py` 里加 `_resolve_quoted_target()` |
| **参与闲聊也不出丑** | `ask_term` —— 不懂就问，而不是硬接一句错的 |

**「不懂就问」是参与闲聊的安全阀**：放宽发言范围之后，模型难免遇到看不懂的词；
这时候问一句，比硬猜着接话要好得多。

## 七、还差的验证

| # | 验证什么 | 怎么看 |
| --- | --- | --- |
| 1 | 它会不会真的用 | 日志里出现「已就「X」在群里提问」 |
| 2 | 会不会滥用 | 统计每天问几次；超过 3 次要看是不是在装不懂 |
| 3 | 答复真的入库了吗 | 问完看 `jargons` 表新增/更新 |
| 4 | 问完会不会接一句 | 日志里提问之后同轮有没有 `reply` |

**第 3 条是这轮的验收线**：问完但没入库，等于白问。

```sql
SELECT content, meaning, is_complete, updated_timestamp
FROM jargons ORDER BY updated_timestamp DESC LIMIT 5;
```

## 八、还想往前一步的话

现在的闭环是「问了才有答案」。可以再进一步：

**让它自己判断「这个词值得问吗」** —— 不是所有生词都值得问，
比如明显的错别字、已有人解释过的、能从前文推断的。

这个判断目前交给模型自己（提示词里写了「猜错了接下来的话就会说错吗？会，就问」）。
如果实测发现它问得太勤或太懒，再改成规则或小模型判别。

**先跑一段时间看真实数据，别提前上机制。**（第 184 轮的教训：先量数据再动手）
