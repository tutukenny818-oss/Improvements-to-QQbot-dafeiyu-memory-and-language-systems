## 〇、一句话结论

**门控判断的是「缓存里最新那条」，Planner 要回的是「它指定的那条」。两者不是同一条。**

Tutu 先发文字、紧跟一张表情包。表情包成了"最新一条"，门控拿它判 → 没名字没问号 → S1 → 拦。
Planner 却一直想回那条文字。

## 二、四处修法

### 2.1 门控按 `msg_id` 定位目标（`reply.py`）

```python
target_text = str(invocation.arguments.get("msg_id") or "").strip()
if target_text:
    for index, candidate in enumerate(window):
        if str(getattr(candidate, "message_id", "") or "").strip() == target_text:
            target_index = index
            break

# Planner 指定了要回的那条 → 用它取代"最新一条"
if 0 <= target_index < len(window):
    latest = window[target_index]
    latest_index = target_index
```

窗口也从 6 条扩到 8 条，容得下「文字 + 图 + 文字 + 图」这种连发。

### 2.2 纯媒体占位文本不当语义依据（`reply.py`）

`[表情包: 委屈,无语,无奈,卑微,尴尬]` 里没有人名、没有问号，单看它永远是 S1。
但它往往紧跟在「你怎么不理我」后面做**情绪加码**，不是话题转换。

```python
if _is_media_placeholder_text(getattr(latest, "processed_plain_text", "")):
    # 往前找最近一条带文字的他人消息，用它来判
```

### 2.3 第二人称 + 疑问/诉求 → I1（`activation_gate.py`）

```
「你怎么不骂我刚刚是假睡觉呢」—— 没名字、没问号、没 @
按旧判据 → S1「别人闲聊」→ 拦
但它明摆着是在问 bot
```

群聊里「你」极少指第三方，配合疑问或诉求词，就是在跟眼前这个对象说话。

**关键约束**：疑问词只在「有『你』」时才升级成 I1。
否则「大肥鱼今天怎么没说话」也会含「怎么」而被放行 —— 那是第三人称议论，必须仍然判 S2。
第一版就是漏了这个约束，`_p205_gate_live.py` 的 S2 拦截率从 88% 掉到 **0%**，回归当场抓住。

### 2.4 对听者埋怨 / 提名字+道别（`activation_gate.py`）

| 句子 | 旧判定 | 新判定 |
| --- | --- | --- |
| 又不回答了 | S1 拦 | **I1**（对听者埋怨） |
| 不理我是吧 | S1 拦 | **I1** |
| 晚安大肥鱼 | S2 拦 | **I1**（提名字+寒暄） |

## 五、这轮最该记住的一条

**「谁被拦」和「谁该被拦」是两个不同的问题。**

前一轮（208）我把门控当成「判据不准」，于是改判断规则。
这一轮才发现更根本的是**判据用错了对象** —— 规则再准，看错消息也没用。

排查时的正确顺序：
1. 门控日志里的 `| 消息=...'` 是**哪一条**？
2. Planner 的 `msg_id` 指向**哪一条**？
3. 两者一致吗？不一致 → 问题在定位，不在判据。

为此在门控日志里加了 `| 目标msg_id=...`，下次一眼就能看出来。
