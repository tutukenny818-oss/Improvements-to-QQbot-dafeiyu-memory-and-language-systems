## 二、三层检索预算（Tier-0/1/2）

### 2.1 依据

[dsh-auto-memory](https://github.com/Aik358/dsh-auto-memory) 的分层设计：

| 层 | 内容 | 预算 |
| --- | --- | --- |
| Tier-0 目录 | 每条一行：标题·结论·层·状态·日期 | ≤800 token |
| Tier-1 摘要 | 每条 ≤140 字，top 8 | 1120 字 |
| Tier-2 原文 | chunk，按需 | ≤2400 字/次 |

**它实测出来的关键坑**：

> 纯按优先级排序会让分层**坍缩**：
> `project` 层 77 个 chunk 吃掉了整个 800 token 预算，
> `whiteboard`/`user`/`log` 一条都没进去。

**修法：每层独立配额。**

### 2.2 实现

`tools\_p205_tiered_budget.py`：

```python
cfg = TieredConfig(
    tier0_budget_chars=1600,
    tier1_budget_chars=1120,
    tier2_budget_chars=2400,
    layer_quota={
        "person": 0.40,   # 人物事实最多占 40%
        "chat": 0.40,
        "episode": 0.30,
        "fact": 0.30,
        "rule": 0.20,
    },
)
result = build_tiered(items, cfg)
```

**防坍缩机制**：
1. 先按层配额分配（第一轮）
2. 有余量才跨层按分数填（第二轮）

### 2.3 自测结果（3/3）

```
Tier-0 目录: 1044 字, 30 行
Tier-1 摘要: 391 字
Tier-2 原文: 817 字
合计: 2252 字（候选 30 条）

[v] Tier-0 不超预算（1044 ≤ 1600）
[v] Tier-1 不超预算（391 ≤ 1120）
[v] 至少两层进入 Tier-0（防坍缩生效）  实际 {'person', 'chat', 'episode'}
```

**测试数据故意让 `chat` 层分数（0.95）远高于 `person`（0.5），
但 `person` 5 条全部进了 Tier-0** —— 证明配额生效。

### 2.4 ⚠️ 实测后决定：**暂不接线**（数据否决了这个计划）

`tools\_p205_ctx_db.py` 只读量了真实数据：

| 会话 | 30 条历史 | 记忆 top-10 | 固定 prompt | **合计** |
| --- | --- | --- | --- | --- |
| 过客群（3221 条） | 1124 token | 1197 token | ~2500 | **≈4800** |
| 会话 B（2107 条） | 3650 token | 1197 token | ~2500 | **≈7300** |
| 会话 C（1333 条） | 4750 token | 1197 token | ~2500 | **≈8400** |

**最大 8400 token，而常见模型窗口是 32k~128k。**

→ **上下文根本没被塞满，三层预算是过度设计。**

这和 dsh-auto-memory 的场景不同：它面对的是**编码 agent 的长任务**
（一次会话几十万 token），我们是**群聊**（一次几百到几千 token）。

**结论：模块留着（`_p205_tiered_budget.py`），但不接线。**
等真的出现上下文档不够用的证据再说。

## 三、这一轮的方法论收获

### 3.1 「主动构造场景」比等真实对话可靠

等真实对话等不到（凌晨没人说话）。
`_p205_gate_live.py` 跑 100 次模拟，**5 分钟就拿到可靠数据**。

这和记忆系统第 187 轮的教训一致：
> 「主动构造场景比等自然发生可靠 —— 等不来就自己模拟那条路径」

### 3.2 时间线是排查的第一手证据

「门控 0 命中」这个问题，本来可以怀疑很多东西：
- 代码没生效
- 日志被过滤
- 判据有问题
- 走了别的路径

**一看时间线就定位了**：插话发生在接线之前。

**下次遇到「改了没效果」，先对时间线。**

### 3.3 静默分支是排查的天敌

门控有 6 个 `return None` 分支，全都不打日志。
导致「0 命中」无法区分是「没跑」还是「跑了但放行」。

**规则：任何门控/拦截逻辑，每个分支都要留痕。**
