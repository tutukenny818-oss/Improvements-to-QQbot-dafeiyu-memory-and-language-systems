## 二、坑二：平均消息间隔没有上限（这才是 67 分钟的来源）

日志原文：

```
17:42:09  回复调度 待处理=1 阈值=2 频率=0.500 平均间隔=4050.84s
          空窗=0.00s 空窗折算=0.00 等效消息数=1.00/2 延迟=4050.84s 判定=延迟检查
```

**延迟 4050.84 秒 = 67.5 分钟。**

### 2.1 为什么会是 4050 秒

上一条消息在 16:34，过客 17:42 说话，间隔 4050 秒。
这个间隔成了「最近 30 分钟平均消息间隔」的**唯一样本**。

```python
average_interval = total_interval / len(self._recent_external_message_intervals)
```

然后它被用来算「还要等多久」：

```python
delay_seconds = max(0.0, (trigger_threshold - pending_count) * average_message_interval - idle_seconds)
```

```
延迟 = (2 - 1) × 4050.84 = 4050.84 秒
```

### 2.2 为什么这是错的

这个「平均间隔」的用途是估「**这个群多久说一句话**」，好判断「一条消息够不够阈值」。

跨过一整段沉默的那一次间隔**不代表群的节奏**，它只代表「中间没人说话」。

拿它当平均值，等于：

> **群里越安静 → 平均间隔越大 → 它反应越慢**

而这正好反了：安静的时候才是最该接话的时候。

### 2.3 修法：加一个上限

原来只有下限（防止连发把间隔拉太低），现在补上限：

```python
IDLE_COMPENSATION_MIN_AVERAGE_INTERVAL_SECONDS = 15.0    # 第 210 轮加的
IDLE_COMPENSATION_MAX_AVERAGE_INTERVAL_SECONDS = 120.0   # 第 217 轮加

clamped = max(average_interval, MIN)
return min(clamped, MAX)
```

**定 120 秒的理由**：
- 群里正常一问一答，间隔一般 10~60 秒；120 秒已是「慢聊」的边界
- 超过 120 秒说明这段时间根本没人聊，不该拿它当节奏样本
- 有上限之后，最坏情况延迟 = **120 秒**，而不是随沉默时长无限增长

### 2.4 效果

```
原始间隔  4050.8s → 夹后  120.0s → 延迟 120s = 2.0 分钟（改前 67.5 分钟）
原始间隔   300.0s → 夹后  120.0s → 延迟 120s = 2.0 分钟
原始间隔    30.0s → 夹后   30.0s → 延迟  30s = 0.5 分钟（正常节奏不受影响）
原始间隔     5.0s → 夹后   15.0s → 仍被下限托住
```

## 三、修坑一时踩出来的第三个坑

把 `mentioned_bot_reply` 打开之后，**凡是出现「大肥鱼」三个字都会强制进 Planner**。
而门控那条分支是**无条件放行**：

```python
if is_mentioned:
    return ActivationDecision(True, "I2", "平台判定提及 bot", 0.7)
```

实测：

```
'大肥鱼今天怎么没说话'   → allow=True   ← 第三人称议论也放行了
'刚才大肥鱼说那个挺好笑'  → allow=True   ← 转述也放行了
```

**这会把它变成话痨。**

### 3.1 改法：`is_mentioned` 不再无条件放行

```python
if is_mentioned:
    if 文本里能找到名字:
        if 带指令词/疑问 或 名字+动词:
            return 放行 I2          # 「大肥鱼猜一个」
        # 只是提到名字 → 落到下面按 S2 处理，交给概率放行
    else:
        return 放行 I2              # 平台说提及但文本找不到（引用形态）→ 保守放行
```

### 3.2 顺带：`猜` 不在指令词表里

第一版改完，「大肥鱼猜一个生活物品」还是被拦：

```
[FAIL] 大肥鱼猜一个生活物品  → S2 allow=False
```

因为「猜」不在 `_ADDRESS_MARKERS` 里，句末是「不是」不是问号。

补充 `_ADDRESS_VERB_PATTERN`：**名字 + 动作动词 + 量词**

```python
r"^(?:[,，、\s]*)(?:猜|来|讲|唱|写|算|看|读|翻|查|找|做|画|放|发|玩|开|问|答|帮|接|想|编|念|背)"
r"(?:一|俩|几|个|首|句|段|条|篇|下|点|遍|什么|啥|一下)"
```

**为什么要量词**：只看动词的话，「刚才大肥鱼**说**那个挺好笑」也会命中「说」——
但那是转述，不是让它在说。

```
大肥鱼猜一个生活物品     → 「猜」+「一个」  → 祈使 ✓
刚才大肥鱼说那个挺好笑    → 「说」+「那个」  → 转述 ✗
```

## 七、这轮的结构性教训

**「延迟几十几分钟」这类症状，要看的是被乘进去的那个因子。**

`delay = (阈值 - 待处理) × 平均间隔`

我第一反应是去看「阈值」和「待处理」——那些都是小整数，没问题。
真正失控的是 `平均间隔`，而它的取值来自一个**没有上限的统计量**。

以后看到「延迟异常大」，先问：**这个数是几个因子乘出来的，哪个因子可能无界？**
