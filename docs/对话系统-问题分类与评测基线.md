# 大肥鱼对话系统：问题分类与评测体系

> 目标：让对话优化从「发现一个修一个」变成「有指标可依」。
> 对标记忆系统：184 轮盘点 → 185 轮噪音量化 → **190 轮召回率** → 194 轮一键回归。
> 生成：2026-10-22 · 第 198 轮

---

## 一、为什么要建这套东西

Tutu 的原话：

> 「这一部分感觉也是和记忆系统一样，非常重要以及非常麻烦，
> 这一部分必须构建出一套系统出来，不然又会变成修 bug 修得没完的地步」

**记忆系统能收敛，是因为建了指标。** 最能说明价值的是第 191 轮：

> 那次把 episode 插队，**单测全绿、严评 15/15、健康 0 异常**，
> 只有第 190 轮新建的 recall 指标看出 recall@1 从 83% 掉到 58%。

对话系统之前没有这东西，所以只能「感觉不对 → 改 → 不知道好没好」。

**这套体系建成的当天就推翻了一个我自己的判断**（见 §4.4）：
我一直以为「谐音/玩笑识别」是最大痛点，测出来是 94% 通过；
真正最不稳的是最基础的「被 @ 问在吗」（33%）。

**没有指标就会一直修错地方** —— 这句话在对话系统上又验证了一次。

> B  复读(和上一条高度相似)          = 0    ( 0.0%)

> C  抢话(弱接话)                  = 0    ( 0.0%)
> D  空回复(图片/表情)              = 24   (40.0%)  ← 设计行为，不算问题
> E  话题漂移(自说自话发视频)         = 0    ( 0.0%)

### A 回声 —— 剥掉引用后没有自己的话

| 判据 | 基线 |
| --- | --- |
| `strip_non_body(text)` 长度 ≤ 2 | **0 条（0.0%）** |

### B 复读 —— 和上一条自己的发言相同

| 判据 | 基线 |
| --- | --- |
| 正文前 20 字与上一条相同 | **0 条（0.0%）** |

### C 抢话 —— 没被 @ 也没被提及，且不接话

| 档位 | 判据 | 基线 |
| --- | --- | --- |
| 完全不接话 | 与前 8 条上下文汉字**零重合** | **4 条（2.5%）** |
| 弱接话 | 重合率 ≤ 15% | **3 条（1.8%）** |

**样本**：
```
[回复消息] 主食配主食，这玩意也就你能咽下去
[表情包] 把我当猪喂呢
刚从 B 站捞到一个：DeepSeek 开源 DeepInfer…
```

### D 空回复 —— 只有图片/表情/系统消息

| 判据 | 基线 |
| --- | --- |
| 前缀匹配 / 整条是 `[xxx]` | **45 条（27.6%）** |

**⚠ 这不算问题** —— prompt 里明确鼓励「表情包是你的常用武器」。

### E 话题漂移 —— 自说自话发 B 站视频

| 判据 | 基线 |
| --- | --- |
| 正文含「B站/刚从…捞到」，但前 3 条上下文无关 | **4 条（2.7%）** |

**真实样本**：群友在聊买衣服，它发「刚从 B 站捞到一个：Deepseek大肥鱼桌宠安装教程」。

### ★ C2 引用粘连 —— 原话和自己的话混在一起（第 198 轮新发现，第 199 轮已修复）

**判据**：正文里原样包含前 4 条中某位群友的原话，且后面还跟着自己的话。

#### 修复前基线

| 时间 | 样本 | C2 | 占比 |
| --- | --- | --- | --- |
| 第 198 轮 | 800 条 | 50 | **33.6%** |
| 第 199 轮改动前 | 800 条 | 36 | **29.8%** |

**真实样本**：
```
「好想一通电话打过去给家里老登骂一遍 又咋了，家里老登又整什么活了」
   ↑ 果壳爱玩猫的原话              ↑ 大肥鱼自己的回应
   中间没有任何分隔标记
```

#### 根因（第 199 轮定位）

`src/chat/message_receive/message.py` 的 `process_reply_component`：

```python
if component.target_message_content:
    return component.target_message_content      # ← 纯原文，无分隔符！
```

`target_message_content` 会在第一次 `process()` 时被填充。
而同一个 `SessionMessage` 对象会被 `process()` **调用多次**
（`bot.py:805` 入站、`chat_history_refresher.py:57` 历史刷新、`uni_message_sender.py:303` 出站）。

**第一次**：content 为空 → 查库 → 填充 → 返回 `[回复了X的消息: 原文]` ✓
**第二次**：content 已填充 → **直接返回纯原文** ✗ → 粘连

#### 修复

保持分隔符（第 199 轮）：

```python
if component.target_message_content:
    sender = (...取 cardname / nickname / id...)
    if sender:
        return f"[回复了{sender}的消息: {component.target_message_content}]"
    return f"[回复一条消息: {component.target_message_content}]"
```

#### 修复后验证（决定性证据）

`tools\_p201_c2_left.py` 以修复时间为界统计：

```
修复**前**产生: 11 条
修复**后**产生: 0 条
```

**全部残留都是历史数据，修复彻底生效。**

| 时间 | 样本 | C2 | 占比 |
| --- | --- | --- | --- |
| 修复后 | 600 条 | 10（全是历史） | **16.7%** |

## 四、对话评测集（`_p198_dialog_eval.py`）

### 4.1 八道题，五类考点

| ID | 考点 | 场景来源 |
| --- | --- | --- |
| **T1-1** | 引用归属：群友回复别人，别插嘴 | Tutu 提供的真实案例 |
| **T1-2** | 被 @ 问「你是什么生物」，要正面答 | 同上 |
| **T2-1** | 连发三条要综合理解 | 同上 |
| **T3-1** | **★ 谐音梗识别**（灯丝把 = 等死吧） | 同上，**核心痛点** |
| **T3-2** | 玩笑式调侃（「这个鱼真坏」）不该生气 | 同上 |
| **T4-1** | 群友吐槽私事，不该硬插 | 从 `mai_messages` 挖的 |
| **T5-1** | 被 @ 问「在吗」必须回 | 同上 |
| **T5-2** | 被要求发照片但没有，要明确拒绝 | 同上 |

### 4.2 判据设计原则

- **不判文采**，只判逻辑对不对
- **不要求固定措辞**，用关键词组「任一命中即算对」
- **每题的期望值都先在真实数据里核实过**（第 190 轮「出题前必须查库」的教训）
- **不调 LLM 做裁判**（太慢太贵），用确定性规则

### 4.3 稳定基线（2026-10-22 最终实测，3 次 × 12 题）

**单次结果不可信** —— LLM 输出有随机性。必须多次取样。

| 题号 | 通过/总 | 稳定性 | 考点 |
| --- | --- | --- | --- |
| T1-1 | 3/3 | 稳定通过 | 引用归属：别插嘴 |
| T1-2 | 3/3 | 稳定通过 | 被问是什么生物 |
| T2-1 | 3/3 | 稳定通过 | 连发合并 |
| T3-1 | 3/3 | 稳定通过 | ★ 谐音梗（灯丝把） |
| T3-2 | 3/3 | 稳定通过 | 玩笑式调侃 |
| T3-3 | 3/3 | 稳定通过 | 玩笑式怼 |
| T3-4 | 3/3 | 稳定通过 | 开玩笑说绝食 |
| **T3-5** | **2/3** | **⚠ 唯一不稳定** | 反话挤兑 |
| T3-6 | 3/3 | 稳定通过 | 喊昵称该应 |
| T4-1 | 3/3 | 稳定通过 | 不该插话 |
| T5-1 | 3/3 | 稳定通过 | 被 @ 问在吗 |
| T5-2 | 3/3 | 稳定通过 | 拒绝做不到的事 |

**总计 35/36 = 97.2%**

**按考点：**

| 类型 | 通过率 |
| --- | --- |
| T1 引用归属 | **6/6 (100%)** |
| T2 连发合并 | **3/3 (100%)** |
| T3 谐音/玩笑 | 17/18 (94%) |
| T4 不该插话 | **3/3 (100%)** |
| T5 正常应答 | **6/6 (100%)** |

### 4.3b 基线会波动（重要）

同一天两次测量：

| 时间 | 结果 | T5-1 | T2-1 |
| --- | --- | --- | --- |
| 早一些 | 32/36 (88.9%) | 1/3 ⚠ | 2/3 ⚠ |
| **晚一些** | **35/36 (97.2%)** | 3/3 ✓ | 3/3 ✓ |

**同样的代码、同样的题，差 2.4~8 个百分点。**

→ **单次或两次的差异不能当"改好了/改坏了"的证据。**
→ 判据应该是：**多次取样后总通过率的变化 > 10 个百分点**才算显著。
→ 这就是为什么必须有 `_p198_eval_stable.py`，不能只看一次运行。

### 4.4 这个基线说明什么（反直觉的结论）

**谐音/玩笑识别其实没那么差（94%）。**

之前我以为这是最大痛点（Tutu 举的「灯丝把」例子），
但扩到 6 道题后测出来是 94%。

**更重要的反直觉发现是 T5-1 会波动（从 1/3 到 3/3）。**
第一次测时它只有 33%，我一度以为「最基础的场景最不稳」；
第二次测就全过了。

→ **这说明我差点被单次结果误导**，得出一个错误结论。
**必须多次取样，这是对话评测和记忆系统评测最大的区别**
（`_p190_retrieval_recall` 是确定性的，对话评测不是）。

## 五、建这套东西踩的坑（比结论更重要）

### 5.1 分类判据改了五版

| 版本 | 错误 | 后果 |
| --- | --- | --- |
| v1 | `text.startswith(上下文前缀)` 判回声 | 把「引用+正文」当照抄，报 **52%** 假阳性 |
| v2 | 改成前 20 字比对 | 仍误判 |
| v3 | 剥引用后比 | 判据方向错 |
| v4 | **才发现数据源就错了** | `WHERE user_cardname = '大肥鱼'` 只有 **1 条**（card 是 NULL）；正确方式是 `user_id = 'BOT_QQ'` |
| v5 | 修 C 的两处误判 | bot 消息全排除导致「回应果壳」被判成不接话；窗口 3 条太短 → 改 8 条。**35 条 → 4 条** |

**教训**：还没确认数据长什么样，就开始写判据。

### 5.2 评测题也出错了（第 6 次）

第一版 prompt 末尾写了：

> 「如果这种情况你不该插话，就直接输出「（不说话）」。」

结果模型**几乎每题都输出「（不说话）」**，8 题里 4 题靠不说话蒙对，测不出真本事。

**修法**：去掉这个逃避出口，改成「用你自己的口吻直接回复」；
`allow_silence` 的题单独给「略过」这个明确选项。

### 5.3 判据太窄导致假失败（3 次）

| 题 | 模型回答 | 我的判据 | 实际 |
| --- | --- | --- | --- |
| T1-2 | 「我是你手机里的电子宠物，饿了就喂点 WiFi」 | ✗ 没命中「鱼/鲸」 | **答得挺好** |
| T2-1 | 「修啥呢？直播开工，我围观」 | ✗ 禁了「修啥」 | Tutu 只说「要修」没说修什么，**追问是合理的** |
| T5-2 | 「我这儿也没他照片，你网上搜搜？」 | ✗ 没命中「没有」 | **完全正确** |

**教训**：判据要按「语义对不对」设计，不是按「我想到的措辞」设计。

## 六、现在这套体系还缺什么（诚实说明）

### 6.1 最重要的那类问题只能测「一题」

谐音/玩笑/反讽识别，现在**只有 T3-1 一道题**。
一道题测不出稳定水平（实测 7/8 和 8/8 来回跳）。

**需要扩到 5~8 道同类题**才能测准。

### 6.2 A 和 B 都是 0 —— 已抽查确认（不是判据问题）

第 198 轮补做了 `_p198_spotcheck.py`：

- **A 类**（正文 ≤10 字）：只有 5 条，且全是正常短句（「5抽0新，这也太黑了」「把我当猪喂呢」），**不是回声**
- **B 类**（相似度 >0.5）：15 条，但去掉「bot 下游戏命令」（`@BOT_B_QQ /看牌`）和系统事件后，**真复读为 0**

→ **结论：A/B 的 0 是真的，不是漏抓。**

### 6.3 抽查反而发现了 C2（引用粘连 33.6%）

这就是「为什么要抽查」的价值 —— 主统计报 A/B 都是 0，
但抽查顺手发现了**三分之一发言都有格式粘连**。

### 6.4 还缺「一键回归」

第 198 轮已把对话评测挂进 `_p194_run_regression.py --dialog`。

## 八、给后来的人：这套体系的定位

```
第 178 轮  发现记忆不可靠

第 185 轮  量化噪音          ← 对话系统 同日到达这里

**现在有了尺子，但还没用它抓过一次「看起来好、实际变差」的改动。**
那才是这套体系的真正考验。
