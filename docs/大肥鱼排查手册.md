# 大肥鱼「没反应」的排查手册

> 2026-10-21 一天之内遇到两次「重启了大肥鱼但没反应」。
> 两次根因不同，但排查路径一样。这份文档把它固定下来 —— **30 秒能定位**。

---

## 一、先看这个：三个必要条件

大肥鱼要说话，这三样**同时**满足才行：

| # | 条件 | 检查 | 不满足的症状 |
| --- | --- | --- | --- |
| 1 | **协议端 3001 在监听** | `Get-NetTCPConnection -LocalPort 3001 -State Listen` | 能启动但**完全不说话** |
| 2 | **嵌入 8898 在监听** | `Get-NetTCPConnection -LocalPort 8898 -State Listen` | 能说话，但**记忆不更新** |
| 3 | **没有残留锁** | 读 `.a_memorix_runtime_writer.lock` 里的 pid，看是否还活着 | 记忆写入失败 |

**一条命令看全**：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 3001,8898,8897,8001,5098,5099,8899 } |
  Select-Object -ExpandProperty LocalPort | Sort-Object -Unique
```

正常应该看到全部 7 个：`3001 5098 5099 8001 8897 8898 8899`

## 二、三种典型故障（都真实发生过）

### 故障 A：能起来但一句话不说

**日志特征**（每 5 秒重复）：

```
[SnowLuma适配器] SnowLuma 适配器连接失败:
  Cannot connect to host 127.0.0.1:3001 ssl:default [远程计算机拒绝网络连接。]；将在 5 秒后重连
```

**根因**：协议端（SnowLuma）没起。

**为什么容易漏**：`bot.py` 自己起得来、WebUI 也能开，看起来"在跑"。
但它**没有 QQ 通道**，收不到消息也发不出去。

**修法**：

```powershell
Start-Process 'D:\SnowLuma\node.exe' -ArgumentList @('D:\SnowLuma\index.mjs') `
  -WorkingDirectory 'D:\SnowLuma' -WindowStyle Hidden
```

等 10 秒左右 3001 会起来（**登录状态会保留，通常不用重新扫码**）。
如果 3001 一直不起来，打开 `http://127.0.0.1:5099` 扫码。

---

### 故障 B：能说话但记忆不更新

**日志特征**：

```
[记忆嵌入] 嵌入维度检测失败，使用 configured_dimension: 512
[记忆嵌入] Embedding 请求失败，重试 1/4，3.0s 后重试: Connection error.
[记忆嵌入] Embedding 请求失败，重试 2/4，9.0s 后重试: Connection error.
```

**根因**：8898 嵌入服务没起。

**后果**：不只是"检索不到"，**写入也会失败** —— 新记忆根本进不去。
所以这个比故障 A 更隐蔽：它照常聊天，只是**记不住任何新东西**。

**修法**：

```powershell
Start-Process 'D:\QQBot\.venv\Scripts\pythonw.exe' `
  -ArgumentList @('-X','utf8','D:\QQBot\tools\embed_server.py','--port','8898') `
  -WorkingDirectory 'D:\QQBot' -WindowStyle Hidden
```

**验证**（返回 200 即正常）：

```powershell
$body = @{ input = @("测试"); model = "bge" } | ConvertTo-Json -Depth 3
Invoke-WebRequest -Uri 'http://127.0.0.1:8898/v1/embeddings' -Method POST `
  -Body $body -ContentType 'application/json' -UseBasicParsing
```

### 故障 C：写不进去（残留锁）

**特征**：健康检查报「DB 完整性」之外的写入类异常，或日志里有锁相关错误。

**根因**：`.a_memorix_runtime_writer.lock` 里记的 pid 对应的进程**已经死了**，
但锁文件还在（异常退出不会自己清理）。

**检查**：

```powershell
$lock = 'D:\MaiBot\data\a-memorix\.a_memorix_runtime_writer.lock'
$c = Get-Content $lock -Raw
Write-Host $c      # 形如 {"lock_path": "...", "pid": 15728}
Get-Process -Id 15728 -ErrorAction SilentlyContinue   # 空 = 已死 = 残留
```

**修法**（移走，不删 —— 便于回滚）：

```powershell
Move-Item $lock "$lock.stale_$(Get-Date -Format 'yyyyMMdd_HHmmss')"
```

**注意**：如果读锁文件时报「另一个进程已锁定」，说明**有活进程在用**，
那是**正常状态**，不要动它。

## 三、★ 我自己踩的两个坑（运维层面）

### 坑 1：绕过标准启动脚本

有 `D:\MaiBot\开机重启大肥鱼.ps1`，它会按顺序检查并拉起：

1. 3001 → 没起就拉 SnowLuma + 打开扫码页
2. 模型桥 8899
3. 嵌入 8898
4. 大肥鱼本体
5. 验证适配器连接（日志搜 `已唤醒|适配器已连接|网关已激活路由`）

**我手动逐个启动，漏了第 1 步**，于是"起来了但没反应"。

**结论：重启就用脚本，别自己拼命令。**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\MaiBot\开机重启大肥鱼.ps1 -SkipWait
```

### 坑 2：用带重定向的方式启动常驻进程

我这样启动：

```powershell
Start-Process ... -RedirectStandardOutput $out -RedirectStandardError $err -PassThru
```

**问题**：输出管道绑定到当前 PowerShell 会话。会话被回收（或工具调用结束），
**子进程跟着结束** —— 日志停在某一行，没有错误、事件日志也没有崩溃记录，
看起来像"神秘消失"。

**正确做法**：不重定向，让它完全脱离。

```powershell
Start-Process -FilePath 'D:\MaiBot\.venv\Scripts\python.exe' `
  -ArgumentList @('-X','utf8','bot.py') -WorkingDirectory 'D:\MaiBot' -WindowStyle Hidden
```

需要看启动错误时，临时用 `-RedirectStandardError` 跑一次**诊断**，
确认没问题后**重新用不重定向的方式起**。

## 四、排查顺序（照这个走，30 秒）

```powershell
# 1. 端口全不全
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 3001,8898,8897,8001,5098,5099,8899 } |
  Select-Object -ExpandProperty LocalPort | Sort-Object -Unique

# 2. 进程在不在
foreach ($p in 'bot.py','SnowLuma','embed_server','asr_server','dfy_panel','_wb_bridge','guoke_bot') {
  $n = (Get-CimInstance Win32_Process -Filter "Name='python.exe' OR Name='pythonw.exe' OR Name='node.exe'" |
        Where-Object { $_.CommandLine -like "*$p*" } | Measure-Object).Count
  Write-Host "$(if($n -gt 0){'OK'}else{'NO'}) $p ($n)"
}

# 3. 适配器连上了没（看最新日志）
$log = Get-ChildItem 'D:\MaiBot\logs' -Filter 'app_*.jsonl' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-Content $log.FullName -Tail 500 -Encoding UTF8 |
  Select-String -Pattern '适配器已连接|网关已激活|对端心跳|连接失败' | Select-Object -Last 3

# 4. 记忆系统状态
& 'D:\MaiBot\.venv\Scripts\python.exe' -X utf8 D:\QQBot\tools\_p179_memory_health.py
```

**判读**：

| 现象 | 结论 |
| --- | --- |
| `对端心跳 ... online=True good=True` | ✅ QQ 连接健康 |
| `连接失败 ... 3001` | → 故障 A |
| `Embedding 请求失败` | → 故障 B |
| 日志停在某行、无错误、无事件 | → 进程被杀（坑 2） |

## 五、不需要担心的"正常现象"

| 现象 | 说明 |
| --- | --- |
| 群里没新消息，日志很安静 | 正常。心跳每 30 秒一次是唯一活动 |
| 读锁文件报「另一个进程已锁定」 | **正常**，说明 bot 在正常写记忆 |
| 健康检查「死段落 5 段」警告 | 有意的撤回（内容是错的），不是故障 |
| 健康检查「摘要游标完整性 50%」 | 老数据，会随新数据自然下降 |
| `get_login_info: 对端未连接` | 启动早期的陈旧日志，3001 起来后自愈 |

## 六、停止时的注意事项

`D:\MaiBot\停止大肥鱼.bat` 的过滤条件是 `CommandLine -like '*MaiBot*'`。

**这个条件会误杀**：`dfy_panel.py` 和 `embed_server.py` 也是用 MaiBot 的 venv 跑的，
命令行里含 `MaiBot`，会被一起杀掉。

**更精确的停止方式**：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -in 'python.exe','pythonw.exe' -and (
    $_.CommandLine -like '*-X utf8 bot.py*' -or
    $_.CommandLine -like '*-m src.runtime*' -or
    $_.CommandLine -like '*src.plugin_runtime.runner*') } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

只杀 bot 本体和它的插件运行时，不碰面板/嵌入/桥。
