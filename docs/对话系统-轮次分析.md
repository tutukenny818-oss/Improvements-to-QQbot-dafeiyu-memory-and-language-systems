## 一、为什么用这篇论文

论文把「多人群聊里 AI 该不该说话」形式化成**每个发言边界的二元决策**，定义四类：

| 类别 | 定义 | 期望 |
| --- | --- | --- |
| **I1** Explicit Address | 被直呼名字/身份 | Speak |
| **I2** Contextual Intervention | 没点名，但作为参与者该回应 | Speak |
| **S1** No Reference | 其他人在聊，你是旁观者 | Silent |
| **S2** Referenced but not addressed | 第三人称提到你 | **Silent** |

**S2 正是 Tutu 报的问题**：「群友提到大肥鱼，但不是在跟它说话」。

### 论文的关键数据（原文引用）

> "We find that they consistently **fail** at context-aware turn-taking under zero-shot prompting."
>
> 8 个 LLM 零样本全部失败，最好的 `gemini-3.1-pro` 只有 **64.45%** balanced accuracy。
>
> S2 类别：**人类标注者只有 27.67% 准确率**（Table 4）。
>
> "context-aware turn-taking is **not an emergent capability**; it must be explicitly trained."

**两个含义：**
1. 这是公认难题，不是我们独有的 bug
2. **不能指望模型自己学会** —— 必须在工程上加约束

## 二、实测：大肥鱼的真实表现

### 2.1 最终数据（1200 条消息样本）

| 类别 | 期望 | 场景 | 说了 | 说话率 | 判定 |
| --- | --- | --- | --- | --- | --- |
| **I1** 被 @ 点名 | 该说 | 11 | 9 | **81.8%** | ✓ 好 |
| **I2** 该回应 | 该说 | 9 | 4 | 44.4% | 偏低 |
| **S1** 别人闲聊 | 该静 | 283 | — | — | 见下 |
| **S2** 被提及没被对话 | 该静 | 21 | 13 | **61.9%** | ★ 硬插 |

### 2.2 S1 拆解（最关键）

600 条样本里，S1 场景下 bot 的回应按类型：

| 类型 | 条数 |
| --- | --- |
| 游戏命令（自己玩，正常） | 1 |
| 纯图片/表情（设计鼓励） | 1 |
| **★ 真插话** | **200** |
| **总回应** | **202** |

**真插话率 70.7%**（200 / 283）。

### 2.3 样本揭示的问题本质

```
群友: 我恢复味觉了
bot : 我恢复味觉了 那第一口得吃口大白饭庆祝下
      ↑ 把对方原话重复一遍

群友: 比我都坏
bot : 比我都坏 坏了你才对得起我
      ↑ 同样

群友: [表情包: 可爱,摸头,安抚,卖萌,宠溺]
bot : 傻福 就这点词汇量，骂人都骂不利索
      ↑ 对表情包也回
```

**规律：几乎每条群消息都回。这不是"判断错了"，是"根本没有抑制机制"。**

## 三、根因（代码层面，两处）

### 3.1 `talk_value = 1.0` → 阈值 = 1

`src/maisaka/runtime.py`：

```python
def _get_message_trigger_threshold(self) -> int:
    effective_frequency = min(1.0, self._get_effective_reply_frequency())   # = 1.0
    return max(1, int(ceil(1.0 / effective_frequency)))                     # = max(1, 1) = 1
```

**每条消息都触发 Planner。**

### 3.2 Planner prompt 强制「必须行动」

`prompts/zh-CN/maisaka_chat.prompt` 原来第 25 行：

> 「不使用工具: 当没有更多操作需要做时，或者等待长时间也没有最新内容时，
> 结束思考，不要调用任何工具，**其他情况都需要调用工具**。」

再加上第 9 行：

> 「在当前场景中，不同的人正在互动（**{bot_name}也是一位参与的用户**）」
> —— 把它定位成"参与者"，不是"旁观者"。

**即使 `group_chat_prompt` 里写了「不要每个人的消息都回复」，也被这两条压过去了。**
这印证了论文的结论：**靠 prompt 里的软性建议无效**。

## 四、改了什么

### 4.1 `prompts/zh-CN/maisaka_chat.prompt`（重点）

新增一整节「先判断这一轮该不该说话」，把论文的四分类搬进来：

| 情况 | 例子 | 该怎么做 |
| --- | --- | --- |
| I1 直接叫你 | `@大肥鱼 你觉得呢` | **必须回** |
| I2 话题需要你 | 有人问没人接的问题 | 可以回 |
| S1 别人在聊自己的事 | 两人聊他们的生活，没提你 | **不要回** |
| S2 提到你但不是跟你说 | `大肥鱼今天怎么没说话` | **不要回** |

并把第 25 行改成：

> 「判断为 S1 / S2（不该说话）→ **直接结束思考，不调用任何工具**。
> 这是正确行为，不是偷懒。……**沉默是安全的默认值。**」

同时把第 9 行的「{bot_name}也是一位参与的用户」
改成「**但群里的对话并不总是围绕 {bot_name} 展开**」。

**备份**：`maisaka_chat.prompt.bak_p200_20261022_004139`

### 4.2 `config/bot_config.toml`

```toml
talk_value = 0.5    # 原来是 1.0
```

推导阈值从 **1 → 2**（需要攒 2 条消息才触发一次）。

**备份**：`bot_config.toml.bak_p200_20261022_004139`

## 七、这一轮我犯的五个统计/验证错误

| # | 错误 | 后果 | 纠正 |
| --- | --- | --- | --- |
| 1 | 把「提到名字」当「叫名字」 | I1 从 100% 低估到 46.7% | 只用 `is_at` 判 I1 |
| 2 | **没排除另一个 bot（果壳）** | I2 从 9 个场景虚增到 92 个 | 读 `bot_platform_accounts` 全部排除 |
| 3 | 窗口太小 | 可能漏掉晚一点的回复 | 实测 1/2/3/5/10/20/40 条，2 条就饱和 |
| 4 | 验证脚本搜「倾向不说话」，实际写的是「倾向于不说话」 | 误报缺失 | 用准确措辞 |
| 5 | 验证脚本搜「其他情况都需要调用工具」，但我在说明文字里引用了它 | 误报残留 | 改成检查「是否在工具列表里」 |

**共同教训：统计口径和验证脚本本身，都要先用真实数据验证一遍。**
