# 多机器人共处：怎么不让两个 bot 互相接话

> 这个群里有另一个机器人（叫「果壳」）。两个 bot 同时在群里，
> 会遇到一堆单 bot 场景不存在的问题。

---

## 〇、先说最容易踩的那个

**在 QQ 眼里，别的 bot 就是一个普通用户。**

报文里 `bot` 字段是 `False` 或者干脆没有。所以如果不特殊处理：

```
大肥鱼说话
  → 果壳当成「群友发言」
  → 喂进耳朵、写进群记忆、送进判断员
  → 果壳可能上去接话
  → 大肥鱼又把它当群友 → 接回去
```

**两个机器人互相接话会滚成循环，两边都在烧模型积分，群里看起来是刷屏。**

---

## 一、四类需要区分的「别人」

| 类型 | 怎么识别 | 处理 |
| --- | --- | --- |
| **普通群友** | 默认 | 正常对话对象 |
| **另一个 bot** | 昵称白名单 / openid / 数据库账号表 | **它说的话不接** |
| **同名的人** | 昵称撞车检查 | 启动时告警，不自动改行为 |
| **自己的消息** | 对比 bot 自己的账号 | 标 `（你）`，不回复自己 |

---

## 二、两种识别方式，各有取舍

### 2.1 按昵称（`FOREIGN_BOT_NAMES`）

```env
FOREIGN_BOT_NAMES=大肥鱼
```

**优点**：立刻能用，不用抓包。
**缺点**：**改个名就失效。**

### 2.2 按 openid（`FOREIGN_BOT_OPENIDS`）

**优点**：准，改名不影响。
**缺点**：得先看到真报文才拿得到。

> **建议：两个都配。** 任意一个命中就算。
> 昵称是快速兜底，openid 是长期正确。

### 2.3 读 `.env` 时必须显式 `load_dotenv()`

这是个真坑：

```python
# handlers.py 自己不做 load_dotenv（那是 config.py 的事）
# 但模块级常量在 import 期就要定值 ——
# 不在这里 load 一次，进程启动时读到的是空字符串
_load_foreign_bots()   # 模块级调用
```

**症状**：配了 `FOREIGN_BOT_NAMES` 但完全没生效，日志里也看不出问题。

---

## 三、两种对策，要同时上

### 3.1 「不听它说的话」——避免循环

识别出是别的 bot 之后：

- 不进耳朵（不作为对话输入）
- 不进群记忆（不写进长期记忆）
- 不进判断员（不触发「要不要接话」的判断）

**只保留一条例外：它 @ 你、或者明确对你发指令时，才处理。**

这就是为什么需要一个命令白名单：

```python
FOREIGN_BOT_CMDS = {"井字棋", "猜词", "24点", "硬币", ...}
# 别的 bot 发这些指令时，照样执行
```

否则两个 bot 就完全没法一起玩游戏了。

### 3.2 「名字撞车要告警」——但不要自动修

**真机背景**：用户的两个号昵称都叫「大肥鱼」，而其中一个 bot 的别名里也留着「大肥鱼」。

后果：群里喊一声「大肥鱼」，**两个机器人都跳出来**。

**这里的正确做法是「只告警，不改行为」：**

- 自动从 `NAME_WORDS` 里摘掉撞车的名字 → 群友叫惯了却不理，体验更差
- 不告警 → 用户根本不知道为什么两个都跳

所以启动时打一条 `WARNING`，让人自己决定怎么改。

---

## 四、名字撞车的三个解法

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| **A. 给其中一个换昵称**（推荐） | QQ 里改昵称 + 同步改 `FOREIGN_BOT_NAMES` | 要重新登录/改名，但一劳永逸 |
| B. 让它只认独有叫法 | 别名里去掉撞车的那个 | **没解决** —— 另一个还是会应 |
| C. 让另一个不认这个名字 | 从它的别名表里摘掉 | 群友叫旧名它不理，**要用户拍板** |

**不要把 C 当默认。** 那是产品决策，不是技术决策。

---

## 五、还有一个隐蔽的坑：记忆里的「另一个 bot」

大肥鱼这边（MaiBot 侧）的识别不能读 `.env` —— 实测 `bot.py` / `runtime.py` 里根本没有 `load_dotenv()`。

**正确的真相来源是数据库**：

```python
def _known_other_bots() -> List[str]:
    # ① 数据库：bot_platform_accounts 里 disabled=0 的账号
    #    → 反查 person_info 拿昵称
    # ② 兜底：.env 里恰好配了也一并收进来
```

`bot_platform_accounts` 表是**两个 bot 都认的**——谁是真 bot 一目了然，不用靠猜。

> **教训**：跨进程/跨 bot 的约定，放在共享存储里比放在各自的环境变量里可靠。

---

## 六、如果你的群里有 3 个以上 bot

同样的逻辑要扩展成：

1. **一个共享的名册**（数据库表最好），记录所有已知 bot 的账号 + 昵称
2. **每个 bot 读同一份名册**，而不是各自维护 `.env`
3. **循环检测**：A 说完 B 说、B 说完 A 说 —— 连续 N 轮就要主动断
4. **发言权让渡**：同一个话题不要两个 bot 都接。可以约定「谁先接谁说话」
