# 刷视频与看视频：让 bot 主动分享和真的看内容

> 两个插件，一出一进：
> **`bili-scout`** 主动去 B 站捞一条发群里；
> **`video-eye`** 别人丢链接时，真的把视频看一遍再说话。

---

## 〇、为什么要分开两个插件

因为它们解决的是**两个不同的问题**：

| | 刷视频 | 看视频 |
| --- | --- | --- |
| 谁发起 | bot 自己 | 群友丢链接 |
| 关键难点 | 别刷成机器人播报 | 别没看就瞎猜 |
| 输出 | 标题 + UP + 链接 + 一句自己的话 | 对内容的真实点评 |

**只做前者**：bot 会变成 RSS 推送器。
**只做后者**：bot 只能被动等链接。
**两个都做**：它既会主动分享，也会认真看你分享的。

---

## 一、刷视频（`bili-scout`）

### 1.1 三个触发入口

| 入口 | 条件 | 说明 |
| --- | --- | --- |
| **手动** | 群友说「刷视频 / 来点视频 / 分享个视频」 | 明确要求，立刻响应 |
| **工具** | `bili_scout` 工具，模型自己决定 | 结合上下文挑时机 |
| **自动循环** | 后台定时 | **默认关，慎用** |

### 1.2 自动循环为什么默认关

自动刷的失败形态非常固定：

```
[17:00] 刚从 B 站捞到一个：《xxx》
[19:00] 刚从 B 站捞到一个：《yyy》
[21:00] 刚从 B 站捞到一个：《zzz》
```

**每两小时复读同一个句式，群里看起来就是机器人播报。**

所以自动循环要配三样东西才敢开：

- 间隔足够长（≥2 小时）
- 每次到点有概率直接跳过（「这轮不想刷」）
- 时间段限制（别在半夜刷）

### 1.3 刷到「说自己」的视频怎么办

这是个很妙的细节 —— 它会先认领一句：

```python
me = _self_ref(title, desc, up)
if me:
    text += "\n（等等，这条好像是在说我？）"
```

**为什么值得做**：bot 刷到夸自己/骂自己的视频，装作没看见很假。
认领一句，反而像个真人在刷自己的 tag。

### 1.4 去重：别推同一个视频

```python
state["posted"] = [...]   # 推过的 bvid 列表
```

**不做去重的后果**：B 站热门榜几天不变，它会连推三天同一条。

### 1.5 别用「一天不超过几次」这种限制

这条是踩过的坑（见 [对话系统/15-玩完要说话](../01-对话系统/15-玩完要说话.md)）：

```diff
- 或者你想主动分享一条 B 站视频时调用。一天不要超过几次。
+ 或者你自己想分享的时候调用。想刷就刷，别重复推同一个视频就行。
```

**用户要的是「想玩就玩」，不是「限量供应」。**
真正要防的是「重复」和「播报腔」，不是「次数」。

## 二、看视频（`video-eye`）

### 2.1 核心问题：模型没看过视频却在点评

这是最容易翻车的地方。典型翻车：

```
群友: [分享了一个视频链接]
bot:  这个视频讲得挺好的，尤其是那部分（其实没看）
群友: 你到底看没看
```

**「看起来像看过」比「承认没看」更糟。**

所以 `video-eye` 的整个设计目标就是：**真的看，看了再说。**

### 2.2 怎么「看」

不是把视频丢给多模态模型（贵且不准），而是**抽帧 + 字幕**：

```
视频文件
  ├─ 抽关键帧（按时间轴）→ 逐帧描述 → 得到「画面时间轴」
  └─ 提取音轨 → ASR 转文字 → 得到「台词/字幕」
                    ↓
        拼成一份「我看了这条视频」的材料
                    ↓
            喂给模型，让它自己说
```

### 2.3 输出格式（关键）

喂给模型的是**结构化材料**，不是一段描述：

```
【我看了这条视频】BV1xxxx
时长：83 秒
画面（时间轴）：
  4.1s 深海背景中，蓝发角色挥手登场，左侧文字「来自深海」
  12.4s 角色眨眼比 OK 手势，弹出「账号移交通知」
  20.6s 双手捧脸惊讶表情
台词：我是来自深海的鲸鱼娘，这个账号现在归我了
```

然后给一句提示：

> 用你自己的一两句话接一下：挑你真觉得有意思/离谱/好笑的一个点，
> 别复述时间轴，别再贴链接，也别解释「我看了视频」这件事。

**最后那句很重要** —— 不加的话，模型会机械复述：
「我看了这个视频，视频里在第 4.1 秒的时候……」

### 2.4 「别解释我看了视频」这条提示

这是从真实翻车学来的：

| 不说这句 | 说了这句 |
| --- | --- |
| 「我看了这个视频，它时长 83 秒，画面里有…」 | 「这谁啊，深海来的还带交接仪式」 |

**前一种是汇报工作，后一种是群友说话。**

## 三、两个插件的联动

真正有价值的场景是**它们接上**：

```
群友分享视频
  → video-eye 自动看（不等被问）
  → 把材料挂在上下文里
  → 之后任何时候被问到，都能接得上
```

而不是：

```
群友: 这个视频讲了啥
bot:  给我链接
群友: [链接]
bot:  我看看
（一轮之后才真的看）
```

### 3.1 预读的时机

**别一收到链接就刷屏说「我看看」。** 正确做法是：

- 后台静默看（不发言）
- 材料准备好之后，**在合适的时候**用上
- 如果有人问「你看了吗」，直接答得上来

---

## 四、踩过的坑

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 自动刷成播报器 | 每 2 小时复读同一句式 | 长间隔 + 概率跳过 + 只挑有上下文的时机 |
| 推重复视频 | 热门榜不变，连推三天同一条 | bvid 去重 |
| 没看就点评 | 被群友当场问「你看没看」 | 抽帧 + ASR，材料没准备好就不说话 |
| 机械复述时间轴 | 「在 4.1 秒的时候…」 | 提示词里明确禁止复述和解释 |
| 一收到链接就说「我看看」 | 刷屏且没内容 | 后台静默预读，不发言 |
| 用次数限制防刷屏 | 变成「限量供应」，用户不满意 | 限制「重复」和「播报腔」，不限制次数 |

## 五、如果你要自己实现

最小可用版本只需要三步：

```python
# 1. 抓热门列表（不需要登录）
#    https://api.bilibili.com/x/web-interface/popular

# 2. 挑一条没推过的
seen = set(state.get("posted", []))

# 3. 拼一句话发出去 —— 关键是这句要像自己说的，不是播报
text = f"刚从 B 站捞到一个：{title} · UP：{up}\n{link}"
```

**但「像自己说的」这步不能省。** 固定模板 = 播报器；
让模型结合当前聊天上下文挑一句话 = 有人在分享。

看视频那边门槛高一些（要抽帧、要 ASR），
但如果你已经有 ASR 服务，剩下的就是**拼材料 + 一句克制的提示词**。
