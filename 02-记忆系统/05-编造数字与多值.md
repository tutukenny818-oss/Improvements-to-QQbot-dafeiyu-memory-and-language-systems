## 二、三次诊断

### 诊断 1（错误）：「时间戳因果反转，用消息时间做换算」

- **说了什么**：`valid_to < created_at`，根因是相对时间按错误 `t_ref` 换算
- **怎么被否**：`SELECT COUNT(*) FROM fact_claims WHERE valid_from IS NULL` → **92/92（100%）**
  代码 `metadata_fact.py:561` 是 `supersede_at = valid_from if not None else now`，
  `valid_from` 全空 → 永远走 `now`，**没有相对时间参与**
- **教训**：报根因前先统计该字段的空值率

### 诊断 2（错误）：「生产代码把纯数字传给 `looks_like_metric_value`」

- **说了什么**：我跑出 `looks_like_metric_value('877') → False`，
  断定这是调用方式 bug，会让**所有**定量事实被挡
- **怎么被否**：读 `ingest_service.py:1022` 原文 —— 传的是 `statement`（整句）：
  ```python
  if not looks_like_metric_value(statement):   # statement 是整句
      return []
  ```
  **是我自己的诊断脚本 `_p195_why_missing.py` 传错了参数**（传了 `val` 而不是 `statement`）
- **教训**：诊断脚本本身也要核对调用签名，别把「我调错了」当成「代码错了」

### 诊断 3（成立）：「`relations` 里的数值是 LLM 编的」

逐条把 `relations` 的数值拿到 `source_paragraph` 原文里搜：

| 边 | 原文含该数字？ | 判定 |
| --- | --- | --- |
| `大肥鱼 --壳币有--> 877` | ✓ 含「壳币增至877」 | 抽取链漏了 |
| `大肥鱼 --壳币数为--> 877` | **✗ 不含**，原文里一个数字都没有 | **LLM 编的** |
| `大肥鱼 --壳币数量--> 967` | ⚠ 段落不存在 | 无法核实 |
| `大肥鱼 --壳币累计达到--> 967` | ⚠ 段落不存在 | 无法核实 |

**验证脚本**：`tools\_p195_final_verdict.py`

## 三、两条写路径策略不同，这是「多值」的来源

| | `fact_claims`（规则抽取） | `relations`（LLM 抽取） |
| --- | --- | --- |
| 触发 | `chat_summary` 段落 | 同一次 LLM 调用返回的 `relations[]` |
| 抽什么 | 只抽**带数值的单值指标** | 什么都抽（含定量、动作、观点） |
| 数值校验 | `extract_metric_value` + 「终结性表述」优先级 | **无** |
| 冲突处理 | 「数值下降不取代」保守策略 | **无** |
| 结果 | 877/967 **被挡在外面** | 877/967 **照样写进去** |

### 具体机制（可复现）

1. 段落 `40f071`「…壳币增至877」→ 规则链**正确抽出 877**
   （实测：`classify_metric` 认出 `guoke.shell_coin`，`extract_metric_value` 返回 `'877'`）
2. 但当时 `fact_claims` 里 active 是 **972**，877 < 972 = **数值下降**
3. 按 docstring 写的保守策略 → **不取代、不写入**
4. 同一次摘要的 LLM 调用在 `relations[]` 里给了 `壳币有: 877` → **没有这条规则** → 写进去了

**所以 4 个值并存不是「抽取坏了」，是两条路径的冲突策略不一致。**
