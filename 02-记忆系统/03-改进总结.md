## 三、修了什么（按影响从大到小）

### 3.1 ★★★ 每天在丢消息：摘要游标失效

**症状**：某些时段有几十条对话，但一个记忆段落都没产生。

**根因链**（跨三个模块）：

```
图片描述触发的摘要 → 不带 trigger_message_count
  → 重启后恢复逻辑退化成 return total（把游标设成"现在"）
    → 重启前那批还没被摘要的消息被永久跳过
```

那天重启了 6~7 次，每次跳过一批。实测 10-20 17:00（39 条）、
18:00（31 条）、23:00（63 条）有消息但零段落。

**修法**（三处）：
1. 写段落时补齐游标（`summary_importer`）
2. 有内容时也记录检查点
3. 缺游标时**用 `event_time_end` 推算**（老数据也能救回来，实测 20/20）

### 3.2 ★★★ 身份认知被污染：大肥鱼否认自己的形象

**症状**：它说自己是「蓝发黑西装」，否认女仆装形象。

**查证**：抽取没错，是它自己被 B 站评论区带偏后说的错话，
摘要如实记录，然后被检索召回，形成自我污染闭环。

**修法**（三层）：
1. **人设层**（最高优先）：`bot_config.toml` 加硬规则，**点名那句错话**
2. **事实层**：2 条 `authority=manual` 权威认知进画像
3. **检索层**：`stale_claims.py` 给旧说法打 `⛔已被推翻,不要采信`

实测对话：问「你长什么样」→「蓝紫渐变长发，深蓝小裙子配绣鲸鱼的围裙，后面还拖着条鱼尾」（6/6 × 3 次全绿）

### 3.3 ★★★ 一条摘要只记到 25%：偏好/承诺类事实全丢

**症状**：92 个对话摘要只有 23 个产出事实（25%）。

**根因**：`_write_summary_metric_claims` 只处理 `cardinality='single'`，
而 `pref.like`、`pref.habit` 全是 `set` → **一条偏好都没抽过**。
查 `profile_section='interaction_preferences'`：**在此之前是 0 条**。

**修法**（两条新路径）：

| 类型 | 依据 | fact_key 策略 |
| --- | --- | --- |
| 偏好（`_write_qualitative_claim`） | VARS 双轨原则（稳定 vs 瞬时） | 复用 `pref.like`，set 多值共存 |
| 承诺（`_write_commitment_claim`） | MS-TOD `confirmation state` | **带日期 + 内容指纹**（有生命周期） |

**关键过滤**（都是实测踩出来的）：
- 瞬时标记（今天/刚才/这局）→ 不写
- 稳定词落在**人名区间内** → 不算（「果壳**爱玩**猫」）
- 承诺词必须在**分号前**（分号后主语换了）
- 值位置验证（防「17 属于大肥鱼却记成过客」）

### 3.4 ★★ 检索排序：试了但失败，已回滚

**问题**：「答应过什么」排第 9（答案是一条 episode，被追加在段落后面）。

**试的方案**：高分 episode 插队。

**结果**：`recall@1` 83% → **58%**（掉 25 个点），换 recall@5 +8 个点。**净负优化，回滚。**

**根因**：段落是余弦相似度（0~1），episode 是加权词法分（0~24.5），
**量纲不同不能混排**。要混排得先做分数校准，需要标注数据。

**这个失败最有价值**：那次改动单测全绿、严评 15/15、健康 0 异常，
**只有新建的召回指标能看出来**。

### 3.5 ★★ 时间上限只对一条路径生效

**症状**：库里 23 条摘要跨度 >2 小时（最长 18.6h），而 `max_window_hours=2.0` 明明配了。

**根因**：`image_description_compensation` 这条写路径**漏传 `window_time_start`**。

**同一位置第 187 轮也漏过**（漏的是游标）——一个功能有多条入口是新 bug 的温床。

**修复后的决定性证据**：

| 分组 | 条数 | 最长 | >2h |
| --- | --- | --- | --- |
| 有 `window_time_start` | 10 | **2.0h** | **0 条** |
| 无（历史） | 91 | 18.6h | 23 条 |

### 3.6 ★★ 2 个插件入口从来没被调用过

**症状**：`bili-scout` 的 `/刷视频`、`video-eye` 的视频预读一次没生效。

**根因**：`bot.py:872` 的 `emit(ON_MESSAGE)` 被注释掉，全仓无别处 emit。

**修法**：补 `chat.receive.after_process` HookHandler（和已验证工作的 human-life 同模式）。

**顺带修**：两条入口的字段名不同（`plain_text` vs `processed_plain_text`）。

### 3.7 ★★ 噪音：episode 通道有零分命中

**症状**：10 条命中里 4 条 episode 是 `score=0`，且与查询无关。

**根因**：`_fuse_branches` 算完 RRF 分**就 pop 掉了**，下游读不到 → 恒为 0.0。

**修法**：改名保留 `fusion_score`；再加 `HEAD_RANK_LIMIT=5` + 相对分数阈值。

结果：episode 零分命中 4 → **0**。

### 3.8 ★ 事实太长：157 字的"事实"

**症状**：摘要整段被当一条事实存，最长 157 字，里面其实 3 件事。

**修法**：
- 定量指标 → 按「主语+指标+值」拼短句（157 字 → 14 字）
- 承诺句 → 取第一个逗号前（61 字 → 20 字，依据 AtomMem 原子事实）

### 3.9 ★ 写入噪音：把"说了一句话"当事实

**症状**：`菜蛆说"喝一碗"`、`Tutu支持大肥鱼` 这类被当事实写入。

**修法**：prompt 加**六类明确排除清单**（一次性的话/临时状态/一次性行为/太模糊/别人的评价/闲聊）。

实测 8/8（4 条噪音全拦下 + 4 条有效事实全记住）。

## 六、12 条踩过的坑（全都有真实事故）

| # | 坑 | 教训 |
| --- | --- | --- |
| 1 | **改 `scope_id` 忘了重算 `conflict_group`** | 派生字段不会自己更新 |
| 2 | **`superseded` 当成 `retracted`** | 「被替代」≠「是错的」，误杀 12 段 |
| 3 | **prompt 加一堆「不要」压死抽取率** | 修一处会压死另一半，长度要盯 |
| 4 | **模型不认抽象规则，只认具体反例** | 同 13 段：抽象 11 个 ep，带反例 5 个 |
| 5 | **改了 prompt 不升版本号** | 重建被判为"可复用"，一条不重算 |
| 6 | **租约不清 `lease_until` 抢不到锁** | 要同时清 status/claimed/token/lease_until |
| 7 | **一个功能多条写入口** | 新参数每条都要补（同位置漏过两次） |
| 8 | **score 跨通道不可比** | 段落 0.27~0.66 vs episode 0~24.5，差 30 倍 |
| 9 | **融合分算完就 pop** | 下游需要的字段不能在中间层删 |
| 10 | **「修了」≠「修对了」** | 改的位置可能只覆盖一半路径 |
| 11 | **验证器只传一个候选 = 验证等于没做** | 必须传全量 |
| 12 | **出题前不查库** | 5 次出题错：ipynb 时间、数据矛盾、547 归属、期望值过时、归属错人 |

## 八、这个阶段最重要的一条方法论

**「建指标」比「改代码」更重要。**

16 轮里最关键的转折不是某个 bug 被修好，而是：
- 第 184 轮建了盘点（八维度）
- 第 185 轮建了噪音量化
- 第 190 轮建了召回准确率

**在建指标之前**：改完只能说「感觉好点了」，改坏了也发现不了。
**在建指标之后**：episode 插队那次，单测全绿、严评 15/15、健康 0 异常，
**只有召回指标能看出 recall@1 从 83% 掉到 58%**。

**没有指标就只能靠感觉，靠感觉就会一直修错地方。**
