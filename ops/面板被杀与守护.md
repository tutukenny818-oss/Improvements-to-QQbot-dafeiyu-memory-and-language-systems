# 第 211 轮 · 面板为什么老是被杀掉

> 「大肥鱼状态面板又没了」—— 不是面板脆，是**每次重启大肥鱼都把它杀掉**。
> 这篇记录根因、修法和新加的守护。

---

## 〇、一句话结论

**面板用 `D:\MaiBot\.venv` 的 python 启动，命令行里带 `MaiBot`，
于是被「重启脚本」和「停止脚本」里那个 `*MaiBot*` 模糊过滤当成大肥鱼本体一起杀了。**

`dfy_panel.py` 从来没有崩过 —— 它每次都死在别人手里。

---

## 一、根因

### 1.1 过滤条件

`开机重启大肥鱼.ps1:135`（改前）与 `停止大肥鱼.bat:5`（改前）：

```powershell
Where-Object { $_.Name -in @('python.exe','pythonw.exe') -and $_.CommandLine -like '*MaiBot*' }
```

### 1.2 面板的命令行

```
"D:\MaiBot\.venv\Scripts\python.exe" -X utf8 D:\QQBot\tools\dfy_panel.py
```

**`D:\MaiBot\.venv` 里就带 `MaiBot`。** 命中，被杀。

### 1.3 实测差别

| 过滤条件 | 命中数 | 含面板 |
| --- | --- | --- |
| 旧：`*MaiBot*` | **10 个** | ✅ 2 个面板被误杀 |
| 新：按模块名精确匹配 | **8 个** | ❌ 不碰面板 |

新条件的 8 个恰好是大肥鱼本体：

```
bot.py × 2 · src.runtime × 2 · src.plugin_runtime.runner × 4
```

### 1.4 交接文档早就记过这个坑

`交接-CURRENT.md` §八：

> **停 bot 按 `*MaiBot*` 过滤** | 各处运维命令 | 会误杀 `dfy_panel` 等同 venv 工具

记了，但没改脚本。所以每次都靠「手动补面板」这个人工步骤兜着。

---

## 二、修法（三层）

### 2.1 过滤条件改精确

`开机重启大肥鱼.ps1` 和 `停止大肥鱼.bat` 都改成按模块名匹配：

```powershell
$_.CommandLine -like '*-X utf8 bot.py*' -or
$_.CommandLine -like '*-m src.runtime*'   -or
$_.CommandLine -like '*src.plugin_runtime.runner*'
```

进程数统计（`$procs`）也用同一条件，口径一致，否则「8 个」这个数字会虚高。

### 2.2 重启脚本自动补面板

以前是「跑完脚本 → 手动补面板」两步。现在脚本最后一步自己检查：

```powershell
if (Test-Port 5098) { Ok '面板已在运行' }
else { 拉起 dfy_panel；等 6 秒；再确认 }
```

### 2.3 新增常驻守护 `dfy_panel_guard.py`

过滤改对了只挡住「被杀」，挡不住「自己崩」。守护补这一层：

| 项 | 值 |
| --- | --- |
| 探测地址 | `http://127.0.0.1:5098/api/state`（**不是探端口**） |
| 间隔 | 20 秒 |
| 连续失败阈值 | 2 次（防网络抖动误杀） |
| 恢复流程 | 杀掉残留面板进程 → 重新拉起 → 等 12 秒复查 |
| 日志 | `D:\MaiBot\logs\dfy_panel_guard.log` |

**为什么探 `/api/state` 而不是探端口**：uvicorn 卡死在某个数据库读上时端口照样开着，
但页面永远转圈。`/api/state` 是页面真正依赖的接口，它通了页面才通。

常用命令：

```powershell
$py = "D:\MaiBot\.venv\Scripts\python.exe"
& $py -X utf8 D:\QQBot\tools\dfy_panel_guard.py --status    # 看状态
& $py -X utf8 D:\QQBot\tools\dfy_panel_guard.py --once      # 查一次
& $py -X utf8 D:\QQBot\tools\dfy_panel_guard.py --recover   # 立刻救一次
& $py -X utf8 D:\QQBot\tools\dfy_panel_guard.py             # 常驻（前台）
```

无窗口常驻：

```powershell
Start-Process "D:\MaiBot\.venv\Scripts\pythonw.exe" `
  -ArgumentList '-X','utf8','D:\QQBot\tools\dfy_panel_guard.py' `
  -WorkingDirectory "D:\QQBot" -WindowStyle Hidden
```

### 2.4 重启脚本顺带拉起守护

`开机重启大肥鱼.ps1` 加了第 7 步：守护没在跑就起一个。这样一次重启后
「面板 + 守护」都在，不需要任何人工补。

## 四、踩到的两个小坑

### 4.1 编辑 PowerShell 脚本必须保 BOM

改完 `开机重启大肥鱼.ps1` 后 `ParseFile` 报 8 个语法错：

```
[X] 语句块或类型定义中缺少右"}"。 @ line 49
[X] 表达式或语句中包含意外的标记")"。 @ line 76
```

补回 UTF-8 BOM 后立刻 **语法 OK**。原文件就是带 BOM 的，编辑器把它去掉了。

> 教训：改 `.ps1` 前后都要 `ParseFile` 检查；补 BOM 用二进制方式写。

### 4.2 写 .bat 必须用 CRLF

`启动大肥鱼面板.bat` 用 LF 写进去，cmd 执行时把整行拆碎：

```
'---------' is not recognized as an internal or external command
'oProfile' is not recognized as an internal or external command
```

转成 CRLF 后正常。Windows 批处理不认 LF。

### 4.3 守护误判「自己在跑」

`--status` 自己就带 `dfy_panel_guard.py` 字样，第一次实现数到了自己 → 永远显示「在跑」。
第二次改成过滤一次性参数，结果又数到了**调用它的那个 pwsh 进程**（命令行里也有这个文件名）。
最终解法：**限定 `Name -in 'python.exe','pythonw.exe'`**。

> 教训：按命令行匹配进程时必须同时限定可执行文件名，否则会命中「提到这个名字的 Shell」。
